# #24 RAG 운영 기준과 해시 이관

## 실데이터 해시 감사

2026-10-15 로컬 PostgreSQL의 `ACTIVE` 혜택 15,234건(정부24 9,953, 지역 4,820, 중앙 461)을 **읽기 전용**으로 검사했다. 재현 명령은 `HASH_AUDIT=1`과 `HASH_AUDIT_PASSWORD` 환경변수를 설정한 뒤 `./gradlew test --tests com.silverhelper.pipeline.performance.ContentHashAuditTests`이다. 기본 테스트에서는 이 감사를 건너뛴다. 접속 대상은 `HASH_AUDIT_URL`, `HASH_AUDIT_USER`로 지정할 수 있다.

| 측정 | 건수 |
|---|---:|
| 저장된 목록 해시와 현재 화이트리스트 해시가 다른 활성 혜택 | 0 |
| 저장된 AI 입력 해시와 현재 화이트리스트 해시가 다른 활성 혜택 | 0 |
| 과거 전체 필드 해시에서 화이트리스트 해시로 바꾸면 달라질 목록 | 9,953 |
| 과거 전체 필드 해시에서 화이트리스트 해시로 바꾸면 달라질 AI 입력 | 9,956 |
| 그중 검증 완료된 혜택 | 513 |
| 검증 완료된 혜택 | 1,053 |
| 현재 검토 대기 항목 | 165 |

현재 DB는 이미 화이트리스트 해시를 저장하고 있어 즉시 재해시할 항목은 없다. 다만 과거 전체 필드 해시를 보유한 DB에 새 코드만 배포하면 목록 9,953건, AI 입력 9,956건의 해시가 달라질 수 있다. 각 혜택을 두 모델로 다시 추출하면 최대 19,912회 호출이다. 이미 미검증인 항목은 원래 처리 대기 중이므로 검증 완료 513건의 **추가** 재추출은 최대 1,026회 호출이며, 해시만 잘못 갱신하면 최대 513건에 거짓 `갱신 확인 중` 표시가 생긴다. 로컬 DB의 `ai_extraction`에는 실모델 토큰 기록이 없어 통화 비용을 신뢰성 있게 계산할 수 없다. 운영에서 AI 추출의 `input_tokens`·`output_tokens`를 모델별 단가에 곱해 산출한다. 외부 AI 키로 시험 호출하지 않았다.

## 배포와 이관

1. 수집·AI 추출 스케줄을 멈추고 DB를 백업한다. 배포 대상 DB에 읽기 전용 감사를 돌려 `stored*Mismatch`, 검증 완료 영향, 검토 대기 건수를 기록한다.
2. 먼저 이 PR의 호환 코드를 배포한다. 재수집 원문을 화이트리스트로 비교해 실질 내용이 같으면 저장된 구형 해시를 유지한다. 이 단계에서 일괄 재해시나 AI 재추출은 없다.
3. 수집 1회를 실행하고 신규·변경 건수, 상세 API 호출, AI 대기열, `content_hash <> verified_hash` 수를 배포 전과 비교한다. 동일 원문만 재수집했는데 증가하면 스케줄을 다시 멈추고 원인을 확인한다.
4. 저장된 해시를 모두 새 값으로 통일해야 한다면 팀장 소유의 별도 Flyway 마이그레이션에서 `benefit_raw`의 구형→신형 해시 대응을 만든다. 동일 신형 해시로 합쳐지는 원문 버전은 `ai_extraction.raw_id`와 `review_item.raw_id` 참조를 정리한 뒤 병합한다. `benefit.content_hash`와 `verified_hash`를 각각 **해당 원문 버전**의 신형 해시로 같은 트랜잭션에서 옮긴다. 기존에 이미 갱신 대기였던 혜택의 두 값을 강제로 같게 만들지 않는다. `rag_embedding.verified_hash`도 함께 옮겨야 기존 공개 근거가 유지된다. 마이그레이션 전후 행 수·참조 무결성·공개 건수·갱신 대기 건수를 대조하고 수집·추출을 재개한다.

공개 검색은 검증된 이전 버전의 `verified_hash`를 사용하며, `content_hash`만 바꾸면 `갱신 확인 중`이 표시된다. 4단계의 공유 마이그레이션은 팀장 배정이 필요하다.

## 채팅 제한과 비용 관측

- JWT `sub`별 Redis 고정 시간창으로 **분당 5회, UTC 일당 50회**를 허용한다. 여러 서버 인스턴스가 같은 제한을 쓴다. 허용된 요청은 근거가 없거나 후속 처리에 실패해도 한도를 사용한다.
- 초과하면 `429`, `CHAT_RATE_LIMITED` 공통 응답 형식, `Retry-After`(초)를 반환한다. Redis가 실패하면 요청을 AI로 보내지 않는다.
- 실제 OpenAI 응답의 usage를 `chat.ai.requests`, `chat.ai.tokens{operation,model,direction}`에 기록하고 모델·입출력 토큰 수만 로그에 남긴다. 질문, 답변, 사용자 ID는 사용량 로그에 남기지 않는다. 운영에서는 모델별 토큰 합계에 계약 단가를 적용하고 일별 추이를 확인한다. 현재 Actuator 웹 노출은 `health,info`뿐이므로 로그 또는 내부 MeterRegistry 수집이 관측 경로다.
- 키가 없는 모의 모델은 외부 비용이 없고 위 AI 사용량 지표에 포함되지 않는다.

## 빈 문서

AI 입력에서 색인할 글이 없는 검증 원문은 `rag_embedding`의 `chunk_no=-1` 완료 표식을 남긴다. 검색은 `chunk_no>=0`만 사용하므로 이 표식은 근거로 반환되지 않는다. `verified_hash`가 바뀌면 새 해시는 다시 색인 대상이 된다.
