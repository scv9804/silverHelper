## 1. 버그 수정 (이슈 #20)
- **전체 혜택 화면의 분류 태그 오류**: 예) "장수수당"에 `입양·위탁`, `서민금융` 태그가 붙음. 원천별 코드 → `WelfareCode` 매핑(특히 정부24)을 실데이터로 검증하고 바로잡는다. 실제 응답 픽스처로 회귀 테스트
- **지역 정보가 없는 지자체 사업이 '전국'으로 노출**: 예) 경주 공원 할인이 서울 사용자에게 '전국'으로 표시. 정부24 소관기관명 등으로 시도·시군구를 보완하고, 보완할 수 없으면 '전국'이 아니라 '지역 확인 필요'로 분류(매칭에서는 `CHECK_NEEDED`)
- 없는 경로는 404 안내 화면
- `/api/regions` 반복 호출 제거(쿼리 캐시)
- 안내 문구를 실제 동작과 일치시킬 것(아래 저장 시스템 결정에 맞춰)

## 2. 저장 시스템 정리
지금은 입력값이 메모리에만 있어서 새로고침·로그인 시 사라지고, 저장 버튼이 이유 없이 비활성화된다. 다음 규칙으로 다시 만든다.

| 상황 | 동작 |
|---|---|
| 비로그인 입력 | `sessionStorage`에 보관(새로고침 유지, 탭을 닫으면 삭제). 화면에 그대로 안내 |
| 비로그인 → 로그인 | 입력값을 **유지**하고, 마이페이지에서 "지금 입력한 정보를 프로필로 저장"을 바로 제안 |
| 로그인 사용자 | 서버 프로필(기존 API)을 기준으로 함. 마지막으로 고른 프로필을 기억(서버 또는 sessionStorage) |
| 로그아웃 | sessionStorage·localStorage의 프로필과 민감 정보 모두 삭제 |
| 관심 혜택 | `saved_benefit` 테이블을 이용해 혜택 저장·해제·목록(로그인 필요). 상세·목록에 저장 버튼, 마이페이지에 목록 |
| 알림 설정 | 마이페이지에 알림 설정 화면(메일 켜기, 새 혜택, 마감 임박 일수). 기존 `/api/me/notification-settings` 사용. 메일을 켤 때 이메일이 없거나 미검증이면 안내 |

- "현재 입력: 75세"처럼 예시값을 입력값으로 보이지 않게(입력 안 한 값은 "미입력")
- 저장 버튼이 비활성화되면 이유를 버튼 옆에 표시
- 민감 정보(소득, 장애·기초수급·보훈)는 localStorage에 쓰지 않는다

## 3. 로컬 데모 가능하게
AI 키가 없으면 공개 혜택이 0건이고 관리자도 만들 수 없어 데모가 불가능하다.
- `local` 프로필 전용 **개발용 관리자 로그인**(운영에서는 빈이 아예 생성되지 않게, 테스트로 보장)
- `local` 프로필 전용 **샘플 공개 시드**: 수집된 혜택 일부를 "개발용 승인" 출처로 공개하는 관리 명령 또는 관리자 API. 공개 화면에 "개발용 샘플 데이터" 표시. 운영 프로필에서는 동작하지 않음을 테스트로 보장
- README에 로컬 데모 순서 정리

## 4. 모바일 대응
- 360~430px 폭에서 가로 스크롤 없이 동작: 상단 메뉴는 모바일에서 접는 메뉴, 카드·폼은 한 줄 배치, 필터는 접기
- 터치 영역 최소 44px, 본문 글자 16px 이상(어르신·보호자 대상이므로 기본 글자를 작게 하지 않는다)
- 화면별로 모바일 폭에서 깨지는 곳이 없는지 확인(가능하면 Playwright 등으로 360px 스크린샷 테스트)

## 5. 외부 호스팅 준비
호스팅 방식은 사용자 결정에 따라 기획 세션이 추가로 지시한다. 그 전까지는 다음까지만 한다.
- 운영 프로필로 한 대의 서버에서 `docker compose`(백엔드 + PostgreSQL + Redis + 프론트 정적 파일을 nginx로 서빙 + HTTPS 리버스 프록시)로 띄울 수 있는 `infra/` 구성. 비밀값은 `.env`로만
- 운영 체크리스트: 개발용 로그인·샘플 시드 꺼짐, Swagger 비활성, CORS·쿠키 설정, JWT_SECRET, DB 백업
- 실제 배포(계정 생성, 결제, DNS)는 하지 않는다

1. **전체 혜택 화면 정리**: 분류 태그 오류와 함께 **필터·버튼 배치가 보기 좋지 않음**. 필터 영역을 정돈된 그리드로 다시 배치하고(검색은 상단 한 줄, 나머지 필터는 2~3열, 모바일은 접기), 검색·초기화 버튼 위치를 일관되게
2. **몇 개씩 보기**: 목록 화면(전체 혜택, 맞춤 결과)에 **10 / 20 / 50 / 100개씩 보기** 선택 추가. 선택값은 sessionStorage에 기억, 바꾸면 1페이지로. 백엔드 `size` 상한이 100 이상인지 확인
3. **호스팅 방식 결정: 먼저 로컬 호스팅, 그대로 AWS로 옮길 수 있게**
   - 5절의 단일 서버 `docker compose` 운영 구성을 **이 PC에서 그대로 실행**한다(운영 프로필, nginx로 프론트 서빙, `/api`는 백엔드로 프록시). 실행 명령 한 줄로 뜨게 `infra/` 스크립트 제공
   - 같은 Wi-Fi의 휴대폰에서 `http://<PC IP>`로 접속해 모바일을 확인할 수 있게 한다(방화벽 안내 포함)
   - 같은 이미지·compose 파일을 AWS(Lightsail 또는 EC2) 한 대에 그대로 올리는 절차를 `docs/deploy.md`에 정리. 도메인과 HTTPS(Let's Encrypt)는 AWS 단계에서 켜지도록 설정으로 분리
   - 로컬 호스팅은 운영 프로필이므로 개발용 로그인·샘플 시드가 꺼진다. 데모 데이터가 필요하면 별도 `demo` 프로필을 두되 운영과 분리하고 화면에 "데모" 표시
