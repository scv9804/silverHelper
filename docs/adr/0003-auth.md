# 0003. 로그인과 회원 정보

- 상태: 승인
- 날짜: 2026-10-14

## 결정

Spring Security OAuth2 Login으로 Google과 Kakao의 사용자 식별자를 확인한다. `(provider, provider_user_id)`로 소셜 계정을 찾고 없으면 `USER` 회원을 만든다. 이메일만으로 계정을 자동 병합하지 않는다. 로그인 성공 시 Redis에 60초짜리 일회용 교환 코드를 저장하고 `/auth/callback?code=...`로 보낸다. 프론트는 `POST /api/auth/exchange`로 코드를 교환한다. 코드에는 회원 정보나 JWT를 넣지 않는다.

서버는 자체 JWT 액세스 토큰(15분, `sub`=회원 ID, `role`, `jti`)을 JSON으로 돌려준다. 리프레시 토큰은 불투명 난수(14일)이며 `HttpOnly`, `Secure`(운영), `SameSite=Lax`, `/api/auth` 경로 쿠키로만 전달한다. Redis에는 토큰 원문 대신 SHA-256 해시를 저장한다. 갱신 시 기존 토큰을 폐기하고 새 토큰으로 교체하며, 로그아웃 시 폐기한다. 액세스 토큰은 프론트 메모리에만 보관한다. `JWT_SECRET`은 운영 환경에서 필수이며 최소 32바이트의 비밀값으로 공급한다.

`USER`와 `ADMIN` 역할을 둔다. 공개 조회 API는 익명 허용, `/api/me/**`·알림 설정·챗봇은 인증 필수, `/api/admin/**`는 `ADMIN`만 허용한다. 관리자 권한은 DB에서 운영자가 확인된 회원 ID의 `user_account.role`을 수동 변경한다. OAuth 제공자 프로필, 이메일 또는 개발용 요청값으로 관리자를 자동 지정하지 않는다. 배포 문서에 변경 절차와 감사 확인을 기록한다.

`POST /api/dev/login`은 `local` 프로필에서만 Bean과 Security 경로를 활성화한다. 개발용 계정은 `DEV` 제공자와 고정된 로컬 식별자로 분리하며 `USER` 역할만 발급한다. 운영 프로필에서는 경로 자체가 없다. 테스트 리소스는 테스트 전용 JWT 비밀값을 생성한다.

회원 정보는 `user_account`, 외부 식별자는 `social_account`, 부모님 프로필은 `parent_profile`에 소유자별로 저장한다. 부모님 프로필의 필드는 기존 `ParentProfile` 매칭 입력과 같다. 프로필 CRUD와 관심 혜택 저장은 로그인한 회원 ID로 범위를 제한한다. 클라이언트가 보낸 소유자 ID를 신뢰하지 않는다.

## 이유

OAuth 제공자 토큰을 서비스 API의 권한 토큰으로 쓰지 않고, 서버의 역할과 세션 폐기를 독립적으로 관리한다. 일회용 코드는 리디렉션 URL에 장기 토큰이 남는 문제를 피한다.
