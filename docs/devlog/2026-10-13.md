# 2026-10-13 프로젝트 시작

- 아이디어 선정: 여행 플래너, 여행지 파티 소셜, 실버 서비스를 비교한 뒤 실버(복지 혜택 안내)로 결정
  - 이유: 공공데이터로 사용자 없이도 실데이터 데모가 가능하고, AI 자동 운영 파이프라인이라는 기술적 포인트가 명확함
- Claude Code로 저장소 뼈대 생성: Spring Boot 4 + React/Vite + docker-compose + CI
- P0-1 공공 API 조사: 복지로 중앙부처·지자체 API와 행안부 공공서비스(보조금24) API 명세를 `docs/specs/public-api.md`에 정리. 장기요양 여부는 어느 API에도 구조화 필드가 없어 AI 추출 대상으로 결정, 중앙부처 API 개발계정이 하루 100건이라 증분 수집 필요
- P0-2 DB 스키마 + Flyway: ADR 0002 작성, `V1__init.sql`로 11개 테이블 생성, ddl-auto는 전 프로필 validate. 중복 사업은 대리 키 그룹(`benefit_group`) + 보수적 자동 병합(이름·기관·지역 일치만, 나머지는 검토 대기열)으로 결정. 공개 여부는 `verified_hash`로 판단
- P0-1b 공공 API 실호출 검증: A 461 / B 4,821 / C 10,965건 확인, [추측] 대부분을 [확인]으로 갱신. A·B의 `age` 파라미터는 믿을 수 없고, C 구조화 연령도 장기요양 사업에서 틀려(19~120세) AI 추출이 필요하다는 결론. 이름 일치 중복은 A의 42%지만 지역이 다른 동명 사업이 많아 자동 병합은 지역 일치 조건 필수. 실제 응답을 테스트 픽스처로 저장. 처음에 모든 API가 "서비스 없음"으로 실패했는데 원인은 Git Bash의 경로 자동 변환이었음
- P0-3 REST API 명세: `docs/specs/openapi.yaml` 작성(혜택 목록·상세, 프로필 매칭, 코드·지역, 관리자 검토 대기열). 매칭은 "조건 NULL = 통과, 프로필 모름 = 확인 필요(CHECK_NEEDED)"로 3단계 판정. 장기요양은 등급/등급 없음/모름을 구분. Redocly lint 통과
- P0-4 패키지 뼈대 + common: 공통 응답(`ApiResponse`, `PageResponse`), 오류 코드·전역 예외 처리, SecurityConfig(`/api/admin/**`만 ADMIN), springdoc 3.1.1, 복지 코드표 enum(`WelfareCode`), Clock 빈, V2 마이그레이션(상세 원문 컬럼). 테스트 25개 통과
