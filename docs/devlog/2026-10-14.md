## 문제와 해결

- 기존 공통 보안 체인과 신규 전역 체인이 겹쳐 PR #14의 첫 CI가 `UnreachableFilterChainException`으로 실패했다. 신규 체인을 `/api/**`와 OAuth 경로로 한정하고 전체 CI로 확인했다. 동일 소셜 계정의 동시 첫 로그인은 DB 트랜잭션 잠금으로 직렬화했다.
- 배포 워크플로 리뷰에서 PR CI를 신뢰할 위험, 오래된 main 버전 재배포, 실행 중 배포 취소, OAuth 경로 라우팅 누락을 확인했다. push CI·저장소·현재 main SHA 검사와 작업별 대기열로 수정하고 `/oauth2/**`, `/login/oauth2/**` 라우팅을 문서화했다.
- 프론트 리뷰에서 화면 이동 후 프로필 수정 대상이 사라지고 일부 검토 사유를 승인할 수 없는 문제를 찾았다. 편집 상태를 유지하고 수동 자격 조건 및 `SOURCE_REMOVED` 승인 경로를 추가했다.
- RAG 리뷰에서 변경된 미검증 원문을 이전 검증 해시로 색인할 수 있음을 발견했다. 검증 해시와 일치하는 보관 원문에서만 새 색인을 만든다. 요약의 연령 조건이 구조화 필드에서 빠지면 검토 대기열로 보낸다.
- SMTP 성공 뒤 DB 상태 기록 실패처럼 발송 여부가 불확실한 경우 자동 재전송하면 중복 메일이 생긴다. 해당 건을 보류하고 [운영 확인 절차](../../backend/src/main/java/com/silverhelper/notification/DELIVERY_RECONCILIATION.md)를 남겼다.
- Claude 최종 리뷰에서 질문 요청마다 200건까지 동기 색인하는 타임아웃·중복 비용 위험과 발송일을 근거 기준일로 오인시키는 메일을 찾았다. 스케줄 색인만 유지하고 검증·수집 시각 및 마감일을 표시했다. 검색 제외·중복 예약·실패 재예약·지역 후보 SQL은 실제 PostgreSQL Testcontainers 테스트로 확인했다.
- 로그아웃 후 부모님 민감 정보가 로컬에 남았고, 3차 리뷰에서 세션 복구 실패·다른 탭 노출 경로도 확인했다. 프로필의 영속 저장을 없애고 이전 키를 삭제하며 세션 변경을 탭 간 전파한다.
- 무프로필 실행에서 기본 `local` 설정이 개발 로그인을 열고 JWT 키 검사를 건너뛰었다. 기본 프로필을 제거하고 테스트 전용 키를 테스트 리소스에 지정해 main CI를 복구했다. 복합 `prod,local`에서는 운영 규칙을 우선하고 기존 카카오 계정의 미검증 이메일을 제거한다.
